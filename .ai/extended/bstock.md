# B-Stock API and scraper reference

**Committed map:** This file is the **scraper-centric** reference aligned with `apps/buying/services/scraper.py`. A longer probe-backed catalog previously lived under **`.ai/reference/`**; that tree is **not** in the repo anymore — treat **`scraper.py`** + this doc as authoritative.

**Valuation (v2.14.0):** Staff auction **`need_score`** and auto **`priority`** are **1–99** integers derived from daily **`CategoryStats.need_score_1to99`** (per taxonomy bucket; **Need v2** since 2026-09-23 = weeks of cover of shelf + pipeline against a target, see `backend.md`) × manifest or AI category weights — see **`apps/buying/services/valuation.py`** and **`.ai/extended/backend.md`** (buying / inventory). Not the same as PO-level **`est_shrink`** (inventory item cost).

## Safe calls, quick check, Buy Now, fresh status (Dash #75, 2026-11-05)

Measured on public calls 2026-11-05 (raw JSON was in `workspace/b75/`):
- **Money is whole dollars** in search (`winningBidAmount`, integer) and anonymous auction state (`startPrice`, `buyNow.price`, `nextMinBidAmount`; `bidPrecision` 1). Never cents: the old ">= 10,000 is cents" rule stored every $10k+ price at 1/100. Manifest retail is the only cents field (its own path). History fix: `fix_bstock_price_slip` (dry run; `--apply` only as an approved Dash request).
- **Buy Now:** search sends `buyNow` (bool) and `buyNowEndTime` (= `biddingStartTime`). While that window is open and there are no bids, `winningBidAmount` is the Buy Now price (11 of 11 matched state `buyNow.price`); after it, a bid. Stored as `buy_now_price` + `buy_now_ends_at` (last values kept); `current_price` is empty inside the window. Auction state: `buyNow: {enabled, price}`, `buyingFormatSequence` `BINO_TO_AUCTION`.
- **Status:** search has no status field; anonymous state has `closed` / `canceled` but no current price. `last_listed_at` is written only by search results. `pipeline.close_ended_auctions()` closes open lots whose end time is over an hour ago (grace so a watched lot gets its last poll), after each sweep and quick check; the upsert uses the same grace and never reopens a cancelled lot.
- **Search:** one call can take several sellers (`storeFrontId` list; 216 public lots = 2 pages of 200); `sortBy: startTime, sortOrder: desc` = newest first; a `buyNow` filter is ignored.
- **Gate (`services/bstock_calls.py`):** every anonymous search / auction-state call passes the kill switch (`buying_bstock_calls_off`), the back-off (a 429 or 403 pauses all calls 5 min, doubling to 2 h; a 2xx clears it; no retry in place) and the hourly cap (`buying_bstock_calls_per_hour`, 300), and is logged in `BStockCall` (14 days; daily totals at `GET /api/buying/bstock-calls/`, superuser, and `manage.py bstock_calls`). Background calls also take `slot()`: a Postgres advisory try-lock (one at a time across dynos, skip after 180 s) and a random 4-12 s gap. Signed-in calls (manifest pull, Costco search) are outside the gate.
- **Sweep:** sellers are searched one after another (no thread pool burst).
- **Quick check (`services/quick_check.py`, `manage.py bstock_quick_check [--loop]`):** one newest-first search of every public seller (about 2 calls) + one state call for watched lots that are due; new lots get a lightweight valuation. **Runs from the Heroku Scheduler every 10 minutes with `--burst`:** inside :00-:04 and :30-:34 it keeps ticking every 60-90 s (80% of lots, 103 of 120 Buy Now lots, went live exactly on the hour on 11-05; Wayfair on the half hour), elsewhere one tick. About 25-30 calls and ~12 dyno-minutes an hour (~$5 a month at Standard-1X rates). Chosen over an always-on worker: beside the Standard-2X web dyno a worker must be Standard-1X (~$25 a month, not the $7 Basic) and would send ~150 calls an hour. Bill (11-05): his call left to the coder. `--loop` (every 60-120 s) stays for a future worker, e.g. ship 2's last-minutes watch.

## API surface (apps/buying/services/scraper.py)

All B-Stock HTTP calls go through `apps/buying/services/scraper.py`. No calls are triggered automatically by page loads or app startup. Every call requires explicit user action (UI button or management command).

**Search:** The public **`search.bstock.com/v1/all-listings/listings`** endpoint accepts **GET** (query params) **or** **POST** (JSON body). The Django app uses **POST** with **`storeFrontId` as an array**, default **`limit=200`**, parallel **ThreadPoolExecutor** per active marketplace (`discover_auctions_parallel`), optional **`BUYING_REQUEST_DELAY_SECONDS`** (default **0**; anonymous pages now use the `bstock_calls` gap instead). Discovery results upsert via raw SQL in **`sweep_upsert`** (preserves **`first_seen_at`** on conflict). **SOCKS5 (v2.14.1):** `*.bstock.com` requests via `_request_json` route through SOCKS5 when `BUYING_SOCKS5_PROXY_ENABLED=True`, except the authenticated manifest pull, which always goes direct. PIA requires `socks5://` (local DNS, `BUYING_SOCKS5_LOCAL_DNS=True`); optional `BUYING_SOCKS5_PROXY_IP` for resolved-IP override. Full setup, troubleshooting, and diagnostic: **[`.ai/extended/vpn-socks5.md`](vpn-socks5.md)**. **Max `limit` = 200** per search request. **Supported path:** **`python manage.py sweep_auctions`** (and staff **`POST /api/buying/sweep/`**); ad hoc parallel scripts are not committed.

**Estimate Profit (Dash Update #73, ship 1, 2026-11-05):** `POST /api/buying/estimate-profit/` (staff, read-only) in `services/estimate_profit.py`; page `/buying/estimate`. **Scored estimates (Dash #77, 2026-11-05):** the measure is **90-day recovery (R90)**: what a truck's items sold for within 90 days of its first sale / its whole manifest retail (qty x unit retail; $0-retail rows left out and flagged; sold items with no manifest row left out and flagged, so R90 runs low there). A truck is scored once its first sale is 90+ days old, and its R90 never changes after. `services/recovery_fit.py` fits per seller (vendor codes TRGET, AMZ, CST, WAL, HMD, WFR; 2026 POs with manifest rows): pooled R90 per seller category and whole truck; a category gets its own rate only on 3+ scored trucks carrying $1,000+ of it and $2,000+ in all (fixed, never tuned on scores); band = quartiles of truck rates with 5+ trucks, else x0.7 / x1.3; under 3 scored trucks = "not yet". Every fit scores each truck **blind** (predicted from a fit without it); stored nightly as a `RecoveryFit` row (with the last fit's median on the same trucks) by `fit_recovery_rates` at the end of `compute_daily_category_stats` (about 30 s; never in a request). Estimate Profit reads the newest fit (switch AppSetting `buying_estimate_rates` = `recovery` default / `sold` the #73 rates, removed next buying ship; before the first fit it uses `sold` and says so); the "How sure" line is the blind test in points and dollars. Every estimate is saved (`EstimateLog`); the **forward score** = a logged estimate whose lot became a PO ordered after that fit, once scored. `GET /api/buying/estimate-scores/?seller=` (staff) feeds "How good is it?" on the result. Local copy 11-05, blind median miss: Target 7.3 points on 8 trucks (no category on 3+ trucks yet, so whole truck 27.9%), Amazon 6.0 on 7, Walmart 3.9 on 5 (3 categories), Costco 9.7 on 3 (thin). A3's 4.9 used sold-to-date on mixed ages.

The old list is `/buying/auctions-old` under the sidebar's Legacy caption with Today's best, Watchlist and Report cards. Tests: `tests/test_live_lots.py`, `LiveLotsPage.test.tsx`.

## Operational safety

Safe operations (no ban risk):
- Opening the dashboard (no B-Stock calls)
- Browsing auctions, manifests, watchlist (DB reads only)
- sweep_auctions without flags (public search — **GET** or **POST** — no JWT)
- CSV manifest upload (local file processing, no B-Stock call)
- **`POST` `/api/buying/sweep/`** from the UI (search discovery only; no JWT) — **Phase 5** may run **Claude** title-category estimates server-side for a limited batch (`ANTHROPIC_API_KEY`), not B-Stock
- Management commands **`recompute_buying_valuations`**, **`estimate_auction_categories`** (DB + optional Anthropic; no B-Stock)

**Manifests (2026-09-22, [`bstock_daily_buying`](../initiatives/bstock_daily_buying.md)):** `GET order-process.bstock.com/v1/manifests/{lotId}` returns the full manifest (up to 1,000 lines a page) **only with the buyer's JWT**. v2.18.0 removed the old anonymous pull (it paged 10 rows at a time) for speed and ban-risk caution; a 2026-09-22 probe found that anonymous calls now always get the same first 10 lines (the response echoes `offset: 0` and `limit: 10`). Accepted `sortBy` values include `_id` (unique, so paging is stable). Flow:
- **Login hand-off.** The superuser's daily **Pull B-Stock manifests** routine (`kind=bstock_pull`, no `system_key`, runs only for superusers, due 11:00, expires end of day) opens a B-Stock seller page. There the owner taps the **Send to Eco-Thrift** bookmarklet (`bstockBookmarklet()` in `frontend/src/pages/routines/runners/bstockHandoff.ts`; it only runs on `*.bstock.com`, and its `#` is written `\u0023` so no browser mistakes it for a fragment). It reads `__NEXT_DATA__.props.pageProps.accessToken` and opens `/routines/bstock-login#t=<jwt>` in a new tab. The hash is not sent to our server but does stay in browser history, which is acceptable for an hour-long token. `main.tsx` moves it to sessionStorage (15-minute life) before routing; the page asks the owner to confirm, then `POST`s `/api/buying/bstock-login/` (superuser), tells the runner tab through a `localStorage` event, and closes itself when a runner tab is open. After a sign-in bounce, `PendingBstockLoginNotice` (staff layout) offers the waiting login. `bstock_token_store.save_token` accepts only a clean three-part JWT with 2 minutes to 2 hours left and swaps it in under an advisory lock (newest row only, never returned by the API). `DELETE` disconnects and stops a running pull.
- **Which token.** The manifest pull sends exactly the handed-over `BStockToken` (`fetch_manifest_items(bearer=...)`), never the token file or env; other JWT calls resolve DB, then `workspace/.bstock_token`, then `BSTOCK_AUTH_TOKEN`.
- **Pull.** Only the routine's Pull button starts one: `POST /api/buying/manifest-pulls/` (superuser; 409 without a live login) starts a `ManifestPullJob` in a daemon thread after commit, or resumes one whose runner died, or returns the running one (advisory lock: one live job). `GET [?job=]` returns `{job, login, shortlist_count, waiting_retry_count}`; `DELETE` stops. The shortlist is fixed at the job's first run. Each auction is claimed under a row lock that re-checks it still needs a pull; CSV upload and manifest delete take the same lock, so a CSV uploaded meanwhile is kept. Every job write is conditional on the runner's ownership token; the heartbeat moves after each page, mapping batch (KEY_MAPPING model and effort from Settings > AI; at most 2 attempts of 60 s, or 90 to 110 s at medium effort or above), and auction; 8 silent minutes make a running job resumable (a queued one after 1 minute), and a resume releases the auction the dead runner had claimed. Stop keeps the result of the auction it interrupted, including one stopped during category mapping.
- **Get manifest, on request (Dash #76, design ship 7).** Superuser button on the auction page (no-manifest card): `POST /api/buying/auctions/{id}/manifest-request/` saves a `ManifestRequest` (requested / pulling / pulled / failed; one open per auction; also Retry), `GET` returns the newest with the line to show (`services/manifest_requests.py`). Refused with the reason when the lot can never be pulled (no lot id, contract, ended, blocked, seller off) or has a manifest. Requested lots skip the window, freshness and retry wait, never the hard checks. **Requests first:** before each auction, any running job (`ManifestPullJob.kind` shortlist or requests) takes the oldest waiting request, then its own list. **Starters:** the tap and a login hand-over start a requests job off the request thread; a job that ends `done` starts the next if one was tapped meanwhile; the 10-minute Scheduler is the backstop. A requests job silent 3 minutes (not 8) is taken over; a request left `pulling` under a dead job waits again; an ended one fails "Ended before it was pulled". **One ceiling for every signed-in pull (both kinds):** before each auction a job stops when the kill switch is on, #75's back-off is active, or signed-in manifest calls (`ManifestPullLog.api_calls`) reach `buying_manifest_calls_per_hour` (200) in the last hour or `buying_manifest_calls_per_day` (600) in the day (AppSettings, editable without a deploy); a 429 from the manifest host starts #75's back-off. A login problem puts requests back to waiting; never blames the lot. **One tap:** the hand-off page (`/routines/bstock-login`) now sends by itself for a signed-in owner and closes (or shows the page he came from); cost: any page that opens that link with a B-Stock login could swap in that login, which only changes whose account pulls manifests into Dash. No password is ever stored and the app never signs in to B-Stock.
- **Scheduler.** `pull_shortlist_manifests` (every 10 min) prunes auto-pulled rows for auctions that ended 14+ days ago, were never watchlisted, and have no recorded Outcome (at most 100 per run, and re-values them; a watchlist entry or an Outcome keeps the manifest until Phase 2 links wins to POs), then resumes dead jobs within a 6-minute budget that also bites between pages. Every job, when it starts or resumes, first finishes category mapping left over from earlier pulls (no login needed). It never starts a pull.
- **What stays on one lot.** 404 (no manifest) and a manifest over 10,000 lines or with no lines mark the auction **blocked** (`manifest_pull_blocked`): never retried, shown on the detail page, cleared by a CSV upload or manifest delete. Another 4xx, paging that came back short, and crashes are recorded on the auction (`manifest_pull_error`, `manifest_pull_attempted_at`) and wait `buying_manifest_pull_retry_hours`. A single 400 / 403 / preview for one lot is recorded as refused.
- **Manifest delete and category mappings.** `DELETE .../manifest/` also removes the AI-made `CategoryMapping`s the manifest brought in (`purge_orphan_ai_mappings`), so a wrong-marketplace CSV leaves no wrong-prefix key behind. A mapping goes only if it is AI-origin, its key is on that auction's rows, no other auction's row uses the key, and it was created after those rows. Seeded and manual mappings, older ones the manifest merely reused, and shared keys stay. Re-uploading over a manifest does not purge.
- **Signed-in-only sellers (Costco).** Anonymous search returns none of Costco's lots; a signed-in search returned all 272 (2026-09-23). `Marketplace.requires_login` (`buying/0025` sets it for `costco`): the sweep searches such a seller with the owner's handed-over login, direct, only while that login is live; with no login it skips the seller with "Signed-in only on B-Stock..." (nothing is closed: auctions close by end time). A pull's first run searches these sellers before fixing its shortlist, so the day's Costco lots can make it. The marketplace chip's tooltip says so. Tests: `apps/buying/tests/conftest.py` makes that search see no login unless a test patches `scraper.login_for_signed_in_sellers`.
- **Fees and shipping.** Fees = `Marketplace.default_fee_rate` x price (B-Stock's 5% buyer fee; `buying/0022` set 5% where blank or the old 3% placeholder), unless overridden. Shipping = override, else `Auction.shipping_quote` (B-Stock's quote), else the **shipping formula** (`services/shipping_formula.py`, AppSetting `buying_shipping_formula`): truckload (`shipmentType` Truckload or 16+ pallets) = fixed + per_mile x miles; LTL = fixed + per_pallet x pallets + per_pallet_mile x pallets x miles, with miles = driving miles from the store to `origin_city` (`ShippingOrigin`, Google Routes, one lookup per new city after each sweep, a failed one again after 30 days; `buying/0024` seeds the 25 cities in our PO history). Fitted 2026-09-23 on 193 POs + 2 B-Stock quotes: truckload $1,668 + $1.67/mi (level x1.62 from 2026 orders, when truckloads jumped), LTL $298 + $43.25/pallet + $0.075/pallet-mile; the page shows amount -/+ the typical miss (25% / 20%). Re-fit: `python manage.py fit_shipping_formula` (report, writes `workspace/shipping_history.csv`: city slug, vendor, pallets, cost, fee, shipping, yyyy-mm) then `--save`, then `recompute_buying_valuations`. No distance: pallets x `buying_shipping_per_pallet` (100). No pallet count: `default_shipping_rate` x price. The sweep stores `pallet_count` (B-Stock `palletCount`, else "23 Pallets" in the title), `origin_city` (`sellerCity, provinceCode`), `origin_zip`, `shipment_type` (Truckload / LTL / PARCEL), and keeps them when a later listing omits them (`buying/0023` also fills pallet counts from old titles). Bulk recomputes load the city rates once. After each saved manifest the pull reads the listing's quote (one more direct call, same pause; a failed quote never fails the manifest). Auction detail has **Get B-Stock quote** (superuser, `POST /api/buying/auctions/{id}/shipping-quote/`: 409 without a login or when B-Stock refuses it, 404 `no_quote`, 502 B-Stock down). Detail also returns `fee_rate_applied`, `shipping_rate_applied`, `shipping_source` so max bid solves for costs that scale with the bid.
- **What stops the job.** A 401, or two different lots refused in a row, means the login: that exact token is forgotten (a newer one sent meanwhile stays), the job fails with "reload B-Stock, then Send again", and the refused lots are cleared back onto the shortlist. B-Stock not answering (timeout, 5xx, 429 after retries; `Retry-After` capped at 60 s) fails the job and parks only the lot it was on. Three failed manifests in a row stop the job unless it was the end of the list; blocked and refused lots do not count. Every attempt writes a `ManifestPullLog` (download time, calls, `used_socks5=False`: authenticated calls always go direct, never through the SOCKS5 pool).
- **Shortlist** (`manifest_pull.shortlist_queryset`): open/closing, seen by a sweep in the last 3 hours, ends within `buying_manifest_pull_window_hours` (36, 1-168), has `lot_id`, not CONTRACT (any case), not archived, not blocked, marketplace active, no manifest rows, no failed attempt within `buying_manifest_pull_retry_hours` (12, at least 1). Watchlisted first, then lots at or under their max (`max_bid`, else `price_target`) ahead of ones already over it (kept, since the target before a manifest is only an estimate), then `priority`, then soonest. Cap `buying_manifest_pull_max_per_run` (40, at least 1); pause `buying_manifest_pull_page_delay_ms` (500) between requests and between auctions. All four under Admin → Assumptions.
- **Save.** Rows normalize with `whole_numbers_are_cents=True` (API retail is integer cents; `renormalize_manifest_rows` does the same for any row whose `raw_data` has an `attributes` dict, then re-values those auctions). Rows are de-duplicated by `_id` and saved only when the unique count equals `total` (with no `total`, paging runs until a short page). `fast_cat_key` = `{vendor}-api-{categories[0]}-{customAttributes.subCategory|otherCategory}`; known mappings are applied first, then the AI (up to 20 batches); mapping trouble or a stop never skips valuation. `Auction.manifest_source` = `auto` / `manual`.
- **Routine.** Submit needs the pull done or stopped, or nothing left to pull (a quiet day, or a failed pull that left every lot in the retry wait). Only a superuser can submit. The run keeps every pull it made (`earlier_job_ids`), so the record shows all results; outcome is always 0 issues.
